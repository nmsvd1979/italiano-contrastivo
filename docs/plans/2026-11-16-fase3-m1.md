# Fase 3 · M1 (app usable offline) — Plan de implementación

> **Para quien ejecute:** usar superpowers:subagent-driven-development (recomendado) o superpowers:executing-plans, tarea por tarea. Los pasos usan casillas `- [ ]`.

**Meta:** una PWA instalable en el iPhone que, sin conexión, haga repaso espaciado (FSRS) y cápsulas A1–A2 de 4 fases con las oraciones ya validadas, con la sesión del día fraccionable.

**Arquitectura:** el pipeline Python genera de forma determinista (sin LLM) los ítems y cápsulas a partir de las oraciones validadas exportadas, y los escribe como JSON en `web/public/content/`. La app (`web/`, Vite + React 19 + TS) solo lee ese JSON, lo valida contra los JSON Schema y guarda el estado del usuario en IndexedDB.

**Stack:** Python 3 (`.venv/bin/python`, pytest, PyYAML), Vite, React 19, TypeScript, vite-plugin-pwa, ts-fsrs 6.0.0 (versión fija), ajv, vitest, fake-indexeddb.

**Spec:** `docs/specs/2026-11-16-fase3-app-design.md` (secciones «Diseño de M1» y «Sesión fraccionable»).

## Restricciones globales
- Rama `feat/fase3-app`; commits en español con el trailer `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. No tocar `data/work/*.db` ni los esquemas (`schemas/*.schema.json` son la fuente de verdad; si un esquema estorba, parar y avisar).
- Texto de interfaz en español neutro con tuteo; sin voseo (`vos`, `tenés`).
- **No inventar italiano:** todo texto italiano mostrado sale de una oración validada o de una transformación mecánica marcada como error (`correct:false` con `error_code` y `distractor_kind`). Un distractor nunca se muestra como correcto.
- Solo se usan oraciones del export (`pivot` excluido; atribución completa). Las generadas por IA (`translation_kind: "llm"`) se marcan «traducción de IA» en pantalla.
- Datos del usuario solo en el dispositivo (IndexedDB). Sin cuentas, sin red, sin rastreo.
- Voz: `speechSynthesis` it-IT del sistema, siempre con la etiqueta «voz del sistema». No hay audio Piper en M1.
- Lo no probado en iPhone real no se declara verificado.
- Pruebas: `npm test` (vitest + pytest) y `npm run typecheck` en verde antes de cada commit de cierre de tarea.

## Enfoque en Review Focus
1. **Distractor que en realidad es italiano válido** (p. ej. «sono vissuto»): cada calco usa listas cerradas y su prueba afirma que el resultado no está en la lista de formas válidas. (Tarea 1)
2. **Código con menos de 3 oraciones utilizables:** no genera cápsula, sin error ni cápsula a medias. (Tarea 3)
3. **Oración etiquetada con el código pero sin el patrón** (o con el patrón dos veces): el generador devuelve `None`, no inventa un hueco. (Tarea 1)
4. **Cerrar la app a mitad de cápsula y cambio de día (medianoche, hora local de Chile):** se retoma desde la última fase completa y el avance del día no se mezcla. (Tareas 5 y 7)
5. **Sin tarjetas vencidas / currículo agotado / IndexedDB no disponible / sin voz it-IT:** cada caso muestra un mensaje en español, nunca una pantalla en blanco. (Tarea 8)

### Tarea 1: Calcos mecánicos por código

**Archivos:** crear `pipeline/exercises/__init__.py`, `pipeline/exercises/calques.py`; test `tests/py/test_calques.py`.

**Interfaces:**
- Produce:
  - `@dataclass(frozen=True) class Calque: code: str; start: int; end: int; correct: str; wrong: str; kind: str` (`kind` ∈ valores de `distractor_kind` del esquema; todos estos son `"l1_calque"` salvo `ERR_PREP_ARTICLE_CONTRACTION` y `ERR_POSSESSIVE_ARTICLE`, que son `"omission"`/`"morphological"` según corresponda; `start:end` es el tramo de la oración italiana que cambia).
  - `def find_calque(code: str, it: str) -> Calque | None` y `CALQUE_CODES: tuple[str, ...]` (los 8 códigos de abajo).

- [ ] **Paso 1: pruebas que fallan.** Por cada código, 2 oraciones reales del export (positivas) y 1 negativa, con las aserciones exactas de abajo; más una prueba paramétrica: `find_calque` devuelve `None` si el patrón aparece dos veces o no aparece.

| Código | Entrada → `wrong` (tramo) | Regla (todas con listas cerradas) |
|---|---|---|
| `ERR_AUX_ESSERE` | «Marco è andato a casa.» → «ha andato» | `è/sei/siamo/siete` + participio inmediato de {andat-, venut-, arrivat-, partit-, uscit-, entrat-, nat-, mort-, salit-, scesо-… (formas o/a/i/e)}; cambia solo el auxiliar a `ha/hai/abbiamo/avete`. No cubre «sono» (ambiguo). |
| `ERR_PREP_PLACE` | «Vivo a Roma.» → «in Roma»; «Vivo in Italia.» → «a Italia» | `a`+ciudad de lista cerrada ↔ `in`; `in`+país de lista cerrada ↔ `a`. |
| `ERR_CE_AGREEMENT` | «Ci sono due libri.» → «C'è due libri»; «C'è un libro.» → «Ci sono un libro» | `ci sono`/`c'è` seguido de determinante/cuantificador de lista cerrada de plural (due, tre, molti, molte, dei, delle…) o de singular (un, una, il, la…). No se aplica si lo que sigue es un participio (-ato/-ito/-uto). |
| `ERR_PERSONAL_A` | «Vedo Marco.» → «Vedo a Marco» | forma de {vedere, conoscere, amare, aspettare, cercare, chiamare} + nombre propio capitalizado (no de la lista de ciudades/países) → inserta ` a`. |
| `ERR_POSSESSIVE_ARTICLE` | «Il mio libro è qui.» → «mio libro» | quita el artículo antes de posesivo singular + sustantivo **fuera** de la lista de parentesco/familia {padre, madre, fratello, sorella, figlio, figlia, nonno, nonna, zio, zia, marito, moglie, cugino, cugina, nipote, papà, mamma, famiglia}. |
| `ERR_PREP_ARTICLE_CONTRACTION` | «Sono nella stanza.» → «in la» | `nel/nello/nella/nell'/nei/negli/nelle, sul…, dal…, del…, al…, alla…` → preposición + artículo separados (`in la`, `a il`…). |
| `ERR_COMPARATIVE_DI` | «È più alto di me.» → «che me» | `più|meno + adjetivo + di` + {me, te, lui, lei, noi, voi, loro, Nombre propio} → `che`. |
| `ERR_TENERE_AVERE` | «Ho fame.» → «Tengo fame» | `ho/hai/ha/abbiamo/avete/hanno` + {fame, sete, sonno, freddo, caldo, paura, ragione, fretta, anni} → `tengo/tieni/tiene/teniamo/tenete/tengono`. |

  Cada caso positivo afirma el `start/end`, `correct` y `wrong` exactos; la prueba de seguridad (Foco 1) afirma que `wrong` nunca pertenece a una lista cerrada de formas válidas (`{"sono vissuto", "ho vissuto", "ho fame", …}` por código) y que `correct` es un fragmento literal de `it`. Usar oraciones reales de `content/sentences/A1.json|A2.json` tras ejecutar `python -m pipeline export` (usa `--authoring-db data/work/authoring.db`); si el export no tiene el patrón, escribir la oración tal cual está en el corpus de Tatoeba validado, no una inventada.
- [ ] **Paso 2: correr** `.venv/bin/python -m pytest tests/py/test_calques.py -q` → debe fallar (módulo ausente).
- [ ] **Paso 3: implementar** `find_calque` con una tabla `{code: función(it)->Calque|None}`; cada función usa regex con límites de palabra y devuelve `None` si hay 0 o ≥2 coincidencias.
- [ ] **Paso 4: correr** las pruebas → pasan.
- [ ] **Paso 5: commit** `Fase 3 M1: calcos mecánicos del español para 8 códigos`.

### Tarea 2: Constructores de ítems

**Archivos:** crear `pipeline/exercises/items.py`; test `tests/py/test_items.py`.

**Interfaces:**
- Consume: `Calque`, `find_calque` (Tarea 1); oración como `dict` con la forma de `schemas/sentence.schema.json`.
- Produce (cada uno devuelve un `dict` que valida contra `schemas/item.schema.json`, con `review_status: "validated"`, `requires_server: false`, `target_error_codes: [code]`, `sentence_id`):
  - `def build_choice(sentence: dict, calque: Calque, seed: int) -> dict` — `type: choice_l1_distractor`; opciones: la oración con `correct` (correcta) y con `wrong` (`correct:false`, `error_code`, `distractor_kind=calque.kind`); orden fijo por `seed`; `prompt_es`: «¿Cuál suena como italiano correcto?».
  - `def build_cloze(sentence, calque) -> dict` — `text` = `it` con el tramo reemplazado por `___` (exactamente uno), `answers=[correct]`, `hint_es` = la oración en español.
  - `def build_reorder(sentence, seed: int) -> dict | None` — solo si la oración tiene 3–9 palabras; `tokens` = palabras mezcladas de forma determinista (distinto del orden correcto), `answer` = orden original.
  - `def build_translate(sentence) -> dict` — `type: translate_es_it`, `source_es=es`, `accepted_it=[it]`, `requires_server:false`.
  - `def item_id(kind: str, sentence_id: str, code: str) -> str`.

- [ ] **Paso 1: pruebas.** Para una oración real por tipo: el ítem valida contra el esquema (usar el mismo validador JSON Schema que usa `pipeline/db/store.py`); `build_choice` tiene exactamente 1 opción correcta y la incorrecta trae `error_code`+`distractor_kind`; `build_cloze` tiene un solo `___`, y `hint_es` **no contiene** ninguna respuesta; `build_reorder` devuelve `None` para una oración de 2 palabras y su `tokens` ≠ `answer` pero mismo multiconjunto; con el mismo `seed` el resultado es idéntico.
- [ ] **Paso 2:** correr → falla. **Paso 3:** implementar. **Paso 4:** correr → pasa.
- [ ] **Paso 5: commit** `Fase 3 M1: constructores de ítems validados`.

### Tarea 6: Repaso espaciado con calibración léxica

**Archivos:** crear `web/src/state/srs.ts`; test `web/src/state/srs.test.ts`.

**Interfaces:**
- Consume: `schemas/data/calibration.json`; `Card` (generado); `createEmptyCard`, `fsrs`, `Rating` de `ts-fsrs`.
- Produce:
  - `function newCard(subject: Card["subject"], lexicalType: Card["lexical_type"], now: Date): Card` — `calibration` según la tabla (`false_friend`: ΔD +2,5 / γs 0,5; `cognate`: −1,5 / 1,8; otros: 0 / 1).
  - `function review(card: Card, rating: 1|2|3|4, now: Date): { card: Card; log: ReviewLog }` — aplica ts-fsrs y luego la calibración: en la **primera** repetición suma `delta_d` a la dificultad (limitada a 1–10) y multiplica la estabilidad por `gamma_s`; si el tipo es `false_friend` y la nota es 1 (lapso), vuelve a multiplicar la estabilidad por `gamma_s`. Recalcula `scheduled_days` y `due` desde la estabilidad nueva (usar `next_interval` de la instancia `fsrs` si es pública en 6.0.0; si no, la fórmula de ts-fsrs para la retención configurada; verificarlo en `node_modules/ts-fsrs`).
  - `function dueCards(cards: Card[], now: Date, limit: number): Card[]` — vencidas primero, más atrasadas antes; tarjetas con `due` futuro no entran (Foco 5).
  - Tarjetas de error de código: `lexical_type:"not_applicable"`. Tarjetas léxicas: solo falsos amigos de `lexemes.json` (cognados y neutros no tienen datos validados en M1).

- [ ] **Paso 1: pruebas.** Con la misma fecha y nota «Bien», una tarjeta `false_friend` termina con `stability` = (la de una `neutral`) × 0,5 y `difficulty` = (la neutral) + 2,5 limitada a 10; una `cognate` con ×1,8 y −1,5 (mínimo 1); la tarjeta resultante valida contra `card.schema.json`; un lapso de falso amigo deja `due` anterior al de una neutral; `dueCards` ignora una `due` de mañana y respeta `limit`.
- [ ] **Paso 2–4:** fallar → implementar → pasar. **Paso 5: commit** `Fase 3 M1: FSRS con calibración léxica`.

### Tarea 8: Pantallas e ítems

**Archivos:** crear `web/src/ui/{TodayScreen,ReviewScreen,CapsuleScreen,AboutScreen}.tsx`, `web/src/ui/items/{Choice,Cloze,Reorder,Translate}.tsx`, `web/src/ui/speech.ts`; modificar `App.tsx`; test `web/src/ui/ui.test.tsx` (humo con Testing Library).
